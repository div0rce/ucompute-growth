# Handoffs to other workstreams

Growth does not edit the engineering, Core Lab or website repositories. Requests go to Website; Engineering and Core Lab are consumed through their records, not through requests (D-032). Program Control reads the first token of each file's `status:` line (proposed, superseded, rerouted, notice, done), so keep it current. Growth writes a dated file here: `YYYY-MM-DD-<workstream>-<topic>.md`, with the ask, the evidence, the exact text or assets, and the claim ids it rests on. The owner or that workstream picks it up in their own session; Growth records the outcome in `journal/LOG.md` and marks the file `status: accepted | declined | superseded` in its front matter.
